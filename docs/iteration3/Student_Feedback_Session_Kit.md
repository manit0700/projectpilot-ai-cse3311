# ProjectPilot AI student feedback session kit

Status: preparation only. No student sessions or results have been recorded in this template.

## Participants and setup

Recruit 3 to 5 students who build small class, hackathon or portfolio applications. Use participant IDs S1 through S5 instead of publishing names. Each session should take about 15 minutes. Do not describe an automated test, developer self-check or peer review as one of these sessions.

Open https://projectpilot-ai-cse3311.vercel.app in a fresh browser profile. Demo mode keeps the task consistent and makes no paid model calls. If live behavior is part of the session, the owner should unlock access privately and obtain consent to the data-sharing notice. Never record a private access code, API key, real coursework secrets or unrelated browser content.

Ask permission to observe and take notes. Obtain separate permission before screen/audio recording. Record the actual date and browser. Participation is voluntary, and the student can stop at any time.

Read aloud: “We are testing the application, not your ability. Please say what you expect to happen. I may stay quiet to see where the interface needs improvement.”

## Task brief

A study-session tracker for one student. The student can add a course and study minutes, list sessions, remove a session and see the total. Data stays in the browser. No login or cloud synchronization is needed for the generated tracker.

## Tasks

1. Start a Demo project using the brief. Explain what the app is asking you to clarify. Answer the questions.
2. Find a requirement and change it to specify positive whole-number minutes. Approve requirements and inspect the task dependencies.
3. Find the usefulness rating. Explain what you think it affects, then change the rating.
4. Approve the task plan, inspect a specialist output and explain whether its review findings need action.
5. Request an output revision that adds invalid-input and empty-state behavior. Explain what changed and what needs approval again.
6. Revisit a previous screen, return to the workflow, and refresh. Check whether the work is still present.
7. Finalize when allowed and download the Markdown. Locate your edited requirement and revision in the downloaded file.
8. Optional keyboard task: use Tab, Shift+Tab, Enter, Space and Backspace to edit a field, correct a typo and activate an approval. Record any focus or navigation difficulty.

Do not coach the participant immediately. Record the point of confusion first. If help is necessary, record exactly what help you gave and mark the task “completed with assistance.” Do not change an unsuccessful task to “passed” because you demonstrated the answer afterward.

## Neutral follow-up questions

- What did you expect the next button to do?
- What information was missing when you made that decision?
- How did you decide whether an output was ready to approve?
- What was easier or harder than your usual approach?
- What would you change first?
